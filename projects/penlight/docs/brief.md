# 应援棒互动游戏 · Claude Code 开发 Brief

Sep 28, 2026 · @Shirakawa Rion

## 背景与目标

做一个晚会中场用的互动游戏：全场观众把手机当应援棒，跟着会场音乐挥动，系统判定每个人挥得稳不稳，大屏实时显示全场同步率，结束后出排行榜，前几名发小奖品。

- **场景**：动漫社迎新晚会中场，跨两个校区同时进行，两边人数不均衡。
- **时长**：一局约 1 分钟（一首歌的副歌段），加上讲规则和颁奖，整体 5 分钟内。
- **参与方式**：扫码打开网页，不装 App，不需要登录，只填一个 QQ 昵称用于领奖。
- **现场效果**：灯光调暗，所有手机屏幕同步变色，像 live 现场的应援棒。
- **排名**：个人赛，与校区无关。人数不均衡不影响公平。

开发分两步：先做**单机 demo** 验证挥动检测和判定手感，再做**联机版**（服务器、大屏、主持控制台）。

## 玩法与判定规则

判定只看「节奏稳不稳、有没有乱挥」，不规定具体的打 call 方式，也没有可见的谱面。核心原则：以每个人自己的挥动习惯为基准。

1. **校准**：开头 8 拍为校准段。取这 8 拍内每次挥动相对最近拍子的偏差（只取 ±0.3 拍以内的），中位数作为此人的个人偏移量。这个偏移同时吸收了个人习惯（挥早或挥晚）和设备传感器延迟。校准段有效挥动少于 3 次时，偏移记为 0 并在结果里标注。
2. **命中**：校准后，每次挥动减去个人偏移，找最近的拍子。偏差在判定窗口 W 内算命中，W = min(100 ms, 0.25 拍)。同一拍的第一次命中计分，第二次起算多余挥动。
3. **回程挥动**：前后挥棒时，拍子中间会出现回挥的加速度峰值。落在两拍之间的第一下不算错也不计分，同一个半拍位置出现第二下才算多余挥动。
4. **打法识别**：结束时统计命中落在偶数拍和奇数拍的比例。命中率低于 65% 且 85% 以上集中在同一奇偶时，判定为「每两拍一下」，只按那一半的拍子算覆盖率。
5. **计分**：

```latex
\text{score} = 100 \times \text{coverage} \times \text{accuracy} \times \max\left(0.5,\ 1 - 0.5 \cdot \frac{\text{extras}}{\text{expected}}\right)
```

其中单次命中得分 = 1 − (|偏差| / W)^1.5，accuracy 为所有命中得分的平均，coverage = 命中拍数 / 应打拍数，上限 1。

- **实时反馈**：每次挥动屏幕闪一下白光，命中闪得更亮。中央大数字显示「近 8 下稳定度」。
- **结果页**：总分、识别到的打法、命中数、平均偏差（毫秒）、多余挥动次数、个人偏移，以及一张偏差分布图。
- **联机版排名**：按总分排序，同分按平均偏差更小者优先。也可以改为「同步率超过某阈值的人进抽奖池」，由主持人现场决定。

## 系统架构

手机负责检测和判定，服务器只管时间和汇总。这样判定不受网络抖动影响，几百人同时在线时服务器压力也很小。

&#91;embedded content: 联机版架构 · 4 类终端\]

手机与服务器双向通信：收开局时间和谱面配置，定期上报实时命中数据和最终成绩。

- **手机端**：单页 Web 应用。扫码进入，填昵称，授权传感器，等待开局。开局后全屏变成应援棒颜色，静音，跟着会场音响挥动。
- **服务器**：Node.js + WebSocket（如 Socket.IO 或 ws）。负责时钟同步、下发“在服务器时间 T 开始”的指令、接收成绩、计算排名。每局数据存内存即可，结束后导出一份 JSON 备份。
- **大屏页**：每个校区一台电脑打开，作为 OBS 浏览器源合成上大屏。收到开局指令后在本地播放歌曲，音频接会场音响。显示全场同步率、参与人数、结束后的前十名。
- **主持控制台**：选歌、开始倒计时、暂停/中止、揭晓排名、标记已领奖。要有简单口令保护。

**时钟同步**：手机和大屏进入时各做几轮 NTP 式往返测量，取往返时间最短的一次估算时钟偏差。会场音响自身的延迟（设备到功放到喇叭再到观众）在彩排时人工测一次，写进每个校区大屏的配置里。个人校准段会吸收剩余误差。

## 技术要点与已踩的坑

第一版 demo 发布在 claude.ai 的 Artifact 里，传感器完全没有数据。原因是页面运行在 iframe 中，父页面没有授权 `accelerometer` 和 `gyroscope`，`devicemotion` 事件不会触发。**必须部署在自己的 HTTPS 域名下直接打开**，不能嵌 iframe（开发期用 GitHub Pages 或本地 HTTPS 隧道即可）。

**传感器与授权**

- iOS 13+ 需要在用户点击事件里调用 `DeviceMotionEvent.requestPermission()`，拒绝后同一会话内无法再弹，需要提示用户去 Safari 设置里重开。
- 优先用 `event.acceleration`（已去重力）；拿不到时用 `accelerationIncludingGravity` 做高通滤波。
- 进入页面后先做一个**传感器自检页**：实时显示加速度模长曲线和识别出的挥动次数，确认有数据再进入等待。2 秒无数据则提示并提供「点屏幕」降级模式。
- 开局后申请 Wake Lock，防止熄屏。

**挥动检测**

- 取加速度模长的峰值时刻作为「这一下」：超过阈值进入峰值状态，记录最大值时刻，回落到阈值一半以下或持续超过 220 ms 时结束。两次挥动间隔至少 160 ms。
- 阈值（m/s²）按灵敏度 5 档：22 / 17 / 13 / 10 / 7。不同机型差异很大，需要用多台 iPhone 和 Android 实测调整，自检页上允许用户自己调。
- 事件时间戳用 `event.timeStamp`，换算到 AudioContext 时间：`ctx.currentTime − (performance.now() − event.timeStamp) / 1000 − outputLatency`。

**节拍与音频**

- 谱面 = 一条节拍网格（BPM + 第一拍时间）+ 分段颜色表。单机 demo 中用 Web Audio 合成了一首 160 BPM、46 秒的测试曲，节拍位置精确已知，建议保留作为测试基准。
- 真歌的 BPM 和第一拍用 **Essentia.js** 的 `RhythmExtractor2013`（multifeature）识别，只分析前 90 秒，然后对拍点做一次网格拟合（相位取圆周平均，周期用最小二乘）。实测 163.4 BPM 的测试鼓点识别为 163.38，相位偏差约 17 ms。
- 识别结果常差一倍，界面需要 ½、×2 按钮和 ±10 ms 微调，并提供「节拍器叠加原曲」的试听，开头和中段各一段，用来检查漂移。
- 联机版的谱面在主持控制台里准备好，开局时随指令下发，手机端不再做识别。
- Essentia 是 AGPL 协议，如果之后开源或对外提供服务需要注意。

**部署与规模**

- 必须 HTTPS（传感器 API 要求安全上下文）。
- 预估同时在线 300 人左右，每人每秒上报不超过 2 次，单机 Node 足够。
- 校园网可能不稳定：手机端在开局前把谱面和开始时间收齐，游戏过程中断网也能继续判定，结束后重试上报。
- 防刷：服务端校验成绩的合理性（命中数不超过拍数、上报时间在该局时间窗内），同一设备同一局只接受一次成绩。

## 开发阶段与验收标准

分三个阶段，每个阶段都能独立拿去现场测。

**阶段 1：单机 demo**（纯前端，部署到 GitHub Pages）

- [ ] 传感器自检页：iPhone 和 Android 各至少 2 台都能看到实时加速度曲线
- [ ] 挥动检测：正常挥 20 下，识别次数误差在 ±1 以内；拿着手机走路不误触发
- [ ] 内置测试曲跑完整局，结果页各项数据正确
- [ ] 上传真歌：自动识别 BPM 和第一拍，试听时节拍器与鼓点听感对齐，½ / ×2 / 微调可用
- [ ] 点屏幕降级模式可用，桌面浏览器也能调试

**阶段 2：联机核心**

- [ ] 服务器、手机端、大屏页三端打通，时钟同步后各手机开局时间误差 < 30 ms
- [ ] 大屏实时显示参与人数、全场同步率；结束后 3 秒内出前十名
- [ ] 主持控制台可以选歌、开始、中止、揭晓排名
- [ ] 模拟 300 个客户端压测通过

**阶段 3：现场彩排**

- [ ] 两个校区的大屏同时开局，各自音响延迟已测量并配置
- [ ] 断网重连、中途进场、刷新页面等异常情况都有处理
- [ ] 奖品认领流程：排行榜显示昵称和一个 4 位认领码，现场核对

**待定问题**

- 用哪首歌、截哪一段（建议 60 秒左右的副歌，节奏清楚、段落分明的偶像番曲目）。
- 排名发奖还是达标抽奖，由社团决定。

## UI 与设计要求

手机端优先，按 360 px 宽度设计，所有页面在这个宽度下不能横向溢出。第一版 demo 在手机上出现过参数卡片和按钮被截断的问题，要避免。

- **风格**：清晰、克制、好看。元素密度合理，不放无用的装饰，功能完整。整体要有明确的风格并保持一致，避免模板化的默认样式。
- **设计 token**：颜色、字号、圆角、间距统一定义为 CSS 变量，同一语义用同一种形式和交互。支持深色和浅色两套主题。
- **图标**：全部来自 SVG 图标库（如 Lucide），不用 emoji，不手画 SVG 图标。
- **二次元元素**：不要堆砌刻板的梗和角色。要埋梗就放在细节里，比如音效、配色或结算页的一行小字，懂的人自己会发现。
- **游戏中的手机屏幕**：整屏就是应援棒的颜色，只保留必要信息（退出按钮、校准进度、近 8 下稳定度、进度条），文字在亮色背景上保证可读。
- **大屏页**：1920×1080，深色背景便于 OBS 合成。字要大，远处能看清，信息只放同步率、人数、倒计时和排行榜。
- **文案**：简短直白，按钮用动词说清楚会发生什么。错误提示说明原因和解决办法。
